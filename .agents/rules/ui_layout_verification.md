# UI Layout Verification and Recursive Self-Correction Rule

## 1. 개요 및 핵심 원칙
- UI 컴포넌트를 추가/수정하거나 테마 미리보기 이미지(스크린샷)를 생성할 때, 에이전트는 **UI 간 문구 간섭(텍스트 잘림, 컨트롤 간 겹침/충돌, 여백 부족, 부자연스러운 줄바꿈)을 스스로 판단하고 재귀적으로 수정**해야 한다.
- 사용자가 레이아웃 결함을 지적하기 전에, 빌드 후 자동 생성된 스크린샷 에셋을 직접 시각적으로 확인(`view_file`)하여 이상 유무를 검토하고 결함이 없을 때까지 스스로 코드를 수정·재빌드하는 자가 개선 루프를 완료해야 한다.

## 2. 필수 검증 체크리스트
1. **다국어(한국어 / 영어) 전수 검증**:
   - 한국어와 영어는 글자 폭과 단어 길이가 다르므로, 언어 전환(KOR ↔ ENG) 시 모든 라벨, 버튼, 체크박스, 드롭다운 콤보박스의 텍스트가 잘리거나 다른 컨트롤을 침범하지 않는지 양쪽 언어 모두 확인한다.
   - 드롭다운(ComboBox) 내부 텍스트(예: "Bottom-Right (Default)")가 선택되었을 때 글자가 생략되거나 잘리지 않는 충분한 너비를 확보한다.
2. **다크 / 라이트 테마 전수 검증**:
   - 다크 모드와 라이트 모드 각각에서 컨트롤의 배경색, 전경 글자색, 테두리 대비가 시인성을 해치지 않는지 확인한다.
3. **컨트롤 간 안전 여백 확보**:
   - 인접 컨트롤 간 및 버튼과의 사이에 최소 16px 이상의 안전 여백을 확보하며, 공간이 부족할 경우 폼 크기를 확장하거나 레이아웃 구조를 모듈화하여 재배치한다.
4. **재귀적 자가 수정 루프**:
   - 스크린샷 검토 시 미세한 간섭이나 겹침이 발견되면 즉시 코드를 수정하고, 다시 빌드 및 스크린샷 생성을 수행하여 시각적으로 완벽함을 확인한 후에만 완료 보고를 진행한다.

## 3. GitHub 미리보기 이미지 영문 게시 원칙
- **GitHub 공개 미리보기는 항상 영문(English) 기준**:
  - `README.md`, GitHub Release 및 저장소 미리보기로 노출되는 에셋(`screenshot.png`, `screenshot_dark.png`, `screenshot_light.png`)은 해외 유저 및 글로벌 공개 환경을 고려하여 **항상 영문(ENG) 버전**으로 생성·게시한다.
  - 한국어 버전은 다국어 검증 및 보조용(`screenshot_ko_dark.png`, `screenshot_ko_light.png`)으로 격리 관리한다.
